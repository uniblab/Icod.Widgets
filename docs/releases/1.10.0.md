# Icod.Widgets 1.10.0 — Win32-Inspired Scrollbars

Icod.Widgets 1.10.0 gives standalone controls and multiline editors one
consistent, themeable scrollbar interaction model on both axes. The behavior is
inspired by Win32 edit and scrollbar controls while remaining terminal-native,
bounded, and Unicode-aware.

## Highlights

- Vertical bars render `▲`, `▼`, `│`, and `┃`; horizontal bars render `◄`, `►`,
  `─`, and `━`. Zero/one-cell areas are inert, two-cell areas retain only the
  arrow buttons, and the two-axis corner is inert.
- Arrow presses step one unit, track presses page, Shift+click or Ctrl+click on
  the track positions directly, and thumb dragging maps safely across the full
  `long` range. Ctrl+click is the portable alias for terminal hosts such as
  Windows Terminal that reserve Shift+mouse for terminal-owned selection.
  Press-and-hold repeat has a 400 ms delay, 50 ms interval, and bounded catch-up.
- Wheel and cross-axis keyboard input use the same semantic scroll commands as
  pointer input. Right-click and Shift+F10 open standard axis-specific context
  menus whose boundary commands disable automatically.
- `WidgetPopupMenu.OpenAt(row, column)` opens a content-sized popup at a screen
  cell, clamping it left or upward when necessary.
- `WidgetEditorOptions.ShowHorizontalScrollBar` opts no-wrap editors into an
  auto-hidden bottom bar. Its stable auto-hide layout composes with the existing
  vertical bar and fixed line-number gutter without visibility oscillation.
- Editor width discovery is incremental and bounded. Visible overflow appears
  immediately, off-screen logical lines are scanned within configured work and
  source-unit limits, and a completed rescan clamps a stale offset after text
  becomes narrower.
- Horizontal scrolling clamps the caret only when it would be stranded, choosing
  a visible Unicode text-element boundary. A caret and selection that remain
  visible are unchanged. Click, drag, repeat, wheel, keyboard, and context-menu
  routes all use this same policy.

## Theme contract

The existing `ScrollTrack`, `ScrollThumb`, and `ScrollFocusedThumb` roles remain
supported. This release adds `ScrollButton`, `ScrollHover`, `ScrollPressed`, and
`ScrollCorner`. Themes control colors and attributes only; they do not change
hit regions, commands, repeat timing, context-menu actions, or caret policy.

## Compatibility

This is an additive public-API release. Existing editor layouts are unchanged
because `ShowHorizontalScrollBar` defaults to `false`. The vertical option also
remains opt-in. Standalone scrollbars retain their public orientation, range,
and `WidgetScrollChangedAction` contract while adopting the expanded interaction
behavior. `AssemblyVersion` remains `1.0.0.0` for 1.x binary compatibility.

## Dedit integration contract

After 1.10.0 is published, Dedit should reference it, enable both scrollbar
options on its document editor, and choose wrapping through
`WidgetTextViewState.WrapMode`. Dedit should continue to own user preferences
and status presentation. Widgets owns scrollbar rendering, hit testing,
context menus, viewport synchronization, bounded width discovery, caret
clamping, and the inert two-axis corner; Dedit should not duplicate those paths.
